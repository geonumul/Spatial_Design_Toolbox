# 정리 슬라이드, 기초 다지기 작성 규칙 (탭하면 한 줄씩 나타나는 슬라이드)

먼저 `00_공통_원칙.md` 와 `work\<과목>\rules\과목정보.md` 를 읽는다.

긴 정리노트는 안 읽힌다. 그래서 주차 내용을 **주제별 단원**으로 나누고, 단원마다 **누를 때마다 한 줄씩 나타나고 넘어가는 슬라이드**로 만든다. 아이패드, 휴대폰에서 본다.

## 1. 원칙

- **한 슬라이드 = 한 가지 생각.** 긴 문단 금지. 한 줄 40자 안팎, 최대 70자.
- 중학생이 읽는다. 어려운 말은 쉬운 말로 먼저 풀고, 그다음 정식 용어.
- 비유 먼저, 정확한 정의는 그다음.
- 반복: 단원 처음 "오늘 알아낼 것", 끝 "다시 한 번". 앞 단원 개념이 나오면 한 줄로 뜻을 다시 붙인다.
- 시험 대비 내용(정의, 목록, 숫자, 규격, 비교)은 빠짐없이.
- 사실은 제공 자료(강의안, 슬라이드, 과목정보의 자료)에서만.
- 이모지 금지.

### 전문용어 자동 암기
- 단원마다 `terms` 4~10개: `{"ko": "동질성", "en": "Homophily", "say": "비슷한 것끼리 연결되는 경향"}` (공통 원칙 3절, 과목 용어 사전 표기 그대로).
- 슬라이드 글에서 용어가 나올 때마다 **매번** `**한국어(English)**`.
- 한 단원 안에서 각 용어가 슬라이드 글에 **3번 이상**(비유, 정의, 그림 설명, 퀴즈, 정리에 골고루). 검사기가 센다.
- 뒤 단원은 앞 단원 용어를 2개 이상 다시 부른다: "앞에서 본 **허브(Hub)** 기억나죠?"
- `check` 중 적어도 1장은 용어 뜻을 묻는다.
- `recap` 마지막 항목은 "오늘의 용어: 허브(Hub), 메시 네트워크(Mesh Network), ..." 한 줄.
- 사이트가 자동으로 하는 것(따로 안 만들어도 됨): 단원 시작 때 앞 단원 용어 복습 카드, 용어 카드, 용어 퀴즈.

## 2. 출력

- 정리 슬라이드: `work\<과목>\notes\slides_w<주차>.json`, 생성 스크립트 `build_slides_w<주차>.py`.
- 기초 다지기: `work\<과목>\notes\slides_wb.json` (week "b"), 생성 스크립트 `build_slides_wb.py`.
- 검사: `python tools\checkers\slide_check.py <파일>` 이 "통과" 할 때까지.

```json
{"week": "3", "title": "3주차. 무선통신 I: 허브와 근거리 무선",
 "units": [
  {"id": "w3-1", "title": "집 안의 반장: 허브", "goal": "이 단원을 마치면 할 수 있는 것 한 줄",
   "terms": [{"ko": "허브", "en": "Hub", "say": "..."}],
   "slides": [ ... ]}
 ]}
```
- 정리 슬라이드는 주차마다 단원 6~10개, 단원마다 슬라이드 10~18장. 단원 id `w<주차>-<번호>`.
- 기초 다지기는 단원 8~10개, 단원마다 14~22장, 단원 id `wb-1` ~ `wb-10`.

## 3. 슬라이드 종류 (kind)

모든 텍스트 필드: 굵게 `**...**`, 필요하면 인라인 수식 `$...$`. 줄바꿈 없음(짧게).

| kind | 필드 | 화면 |
|---|---|---|
| `title` | `big` (큰 제목, 20자 이내), `sub` (한 줄) | 단원 첫 장. 반드시 단원마다 첫 슬라이드 |
| `goal` | `items` (2~4개) | "오늘 알아낼 것". 두 번째 슬라이드 |
| `points` | `head`, `items` (2~5개) | 탭할 때마다 한 줄씩 |
| `analogy` | `head`, `scene` (비유 장면 1~2문장), `map` ([["비유 속 것", "진짜 개념"], ...] 2~4쌍) | 비유와 짝 맞추기 |
| `formula` | `head`, `tex` (TeX, $ 없이), `parts` ([{"sym": "TeX 조각", "say": "쉬운 말 뜻"}] 2~6개), `whole` | 식, 기호가 하나씩, 마지막에 우리말 |
| `steps` | `head`, `given` (선택), `steps` (3~7개), `answer` | 계산이나 동작 순서가 한 단계씩 |
| `figure` | `head`, `svg`, `caption`, `builds` (1~5) | 그림이 단계별로 그려짐 |
| `compare` | `head`, `cols` (2~4개), `rows` ([["행 이름", "값", ...]] 2~6행) | 행이 하나씩 |
| `english` | `head`, `en` (외워 쓸 답안 문장), `ko` (핵심 풀이), `tip` (선택: 외우는 요령) | 문장 먼저, 탭하면 풀이 |
| `check` | `q`, `choices` (2~4개), `a` (정답 인덱스), `why` | 눌러서 답하는 퀴즈. 단원마다 1~3장 |
| `warn` | `head`, `items` (1~3개) | 헷갈리기 쉬운 점 |
| `recap` | `items` (3~5개) | "다시 한 번". 단원 마지막 슬라이드 |

단원마다 반드시: title(첫 장), goal, 1개 이상의 analogy, 1개 이상의 figure, 1개 이상의 check, recap(마지막 장). 숫자 계산이 시험에 나오는 단원은 steps 필수.

## 4. SVG (figure.svg, 사이트용)

- 올바른 XML, `viewBox="0 0 480 270"` (필요하면 높이만 300까지), width/height 속성 없음, **`id` 금지, `style` 속성 금지, fill/stroke 색 값 금지, `stroke-width` 금지, `font-family` 금지.** 대신 **클래스로만** 꾸민다(사이트가 밝은/어두운 테마 색을 입힌다):

| 클래스 | 용도 |
|---|---|
| `n` | 기본 도형(원, 사각형 노드) |
| `n2` | 강조 도형(주인공) |
| `n3` | 두 번째 색 도형 |
| `n4` | 세 번째 색 도형(주의, 틀림) |
| `e` | 선 |
| `e2` | 강조 선(흐름) |
| `arrow` | 화살표 머리 (polygon) |
| `t` | 글자 |
| `tb` | 굵은 글자 |
| `tm` | 흐린 글자 |
| `tl` | 도형 안 글자 |
| `box` | 둥근 사각 패널 |
| `box2` | 강조 패널 |
| `hl` | 강조 테두리 |

- 단계별로 나타날 요소에 `b1`, `b2`, ... 를 함께 붙인다(예 `class="e2 b2"`). `builds` 는 가장 큰 b 번호(없으면 1).
- 글자 크기는 `font-size` 속성 14~20. `text-anchor` 사용 가능.
- 도형: circle, line, rect, polygon, polyline, path(짧게), text. 선 굵기는 사이트가 정한다.
- **사각형 모서리는 둥글리지 않거나 아주 조금만**: `rx` 는 0~3. 알약처럼 둥근 상자 금지(사용자 요청).
- 겹치는 글자 없게. 가능하면 PNG 로 렌더해서 직접 확인한다(클래스 색은 임시로 입혀서).

## 5. 기초 다지기에서 달라지는 점

- 과목에 필요한 선수 지식을 **0부터**. 과목정보의 "기초 다지기 단원 후보" 를 따른다.
- 단위와 기호는 소리 내 읽듯이("dB 는 데시벨"). 숫자가 있는 개념은 반드시 쉬운 숫자로 손계산(steps), 계산은 Python 으로 assert.
- 단원 recap 바로 앞 슬라이드는 `points`, head "이게 이 과목 어디에 나오나": 주차, 주제, 시험에서 나오는 모양.
- 그림, 퀴즈를 정리 슬라이드보다 더 많이.
