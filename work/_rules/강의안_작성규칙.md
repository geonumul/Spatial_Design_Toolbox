# 강의안 작성 규칙 (슬라이드 + 떠먹여주는 대본 PDF)

먼저 `00_공통_원칙.md` 와 `work\<과목>\rules\과목정보.md` 를 읽는다.

결과물은 PDF 다. 쪽마다 위에 원본 슬라이드가 한 장, 그 아래에 이 강의안이 2단으로 흘러간다. 학생은 수업 없이 이 강의안만 읽고 슬라이드를 완전히 이해하고 시험을 볼 수 있어야 한다. 이 강의안은 회독 레슨(사이트)의 주 자료로도 쓰인다.

## 1. 파일

- 출력: `work\<과목>\lecture\<덱>_<시작쪽3자리>-<끝쪽3자리>.md` (예 `I3_001-016.md`). UTF-8.
- 쪽마다:
```
## p.12 슬라이드 제목(한국어)
### 대본
(본문)
```
- 슬라이드 그림: 작성용 PNG `work\<과목>\_src\png\<덱>\pNNN.png` 를 **반드시 Read 도구로 직접 본다.** 표, 그림, 도식의 의미를 정확히 설명하려면 봐야 한다. 텍스트 추출본이 있으면 철자 확인용으로 같이 쓴다.
- 다 쓰면 `python tools\checkers\lecture_check.py <파일> <시작> <끝>` 이 "결과: 통과" 가 될 때까지 고친다.

## 2. 쪽마다 쓰는 순서 (내용 슬라이드)

슬라이드 성격에 맞지 않는 칸은 뺀다. 단 `:::key` 와 `:::repeat` 는 내용 슬라이드에 반드시 넣는다.

1. `:::key` 블록: 이 슬라이드가 하려는 말 한 문장(많아야 두 문장).
2. 연결 문단: "앞 슬라이드에서 ~를 봤죠. 이번 슬라이드는 그다음으로 ~를 봐요." 앞 내용을 한 번 더 짧게 되풀이.
3. `#### 슬라이드 글자 하나씩 읽기`: 슬라이드의 모든 문장, 불릿, 표 칸을 빠짐없이 짚고, 문장마다 "무슨 뜻인지" 일상어로. 그림과 도식도 "왼쪽 위에 ~가 있고, 화살표는 ~ 뜻" 식으로 읽어 준다. 슬라이드에 있는 숫자, 규격, 이름, 연도는 하나도 빼지 않는다.
4. 처음 보는 개념이면 `:::bg` 블록(배경 지식): 과목을 처음 듣는 학생이 이것만 읽고 알 수 있게 짧게 가르친다(예: 주파수가 뭔지, 단열이 뭔지). 기초 다지기 단원과 연결되면 "기초 다지기 4단원에서 자세히" 라고 적는다.
5. 숫자가 나오면 `#### 숫자로 직접 해보기` 또는 `:::step` 블록: 쉬운 숫자로 한 단계씩 계산하거나 비교(표 적극 사용). 시험 계산 모양과 같게.
6. `:::fig 캡션` 블록: 슬라이드에 없는 새 SVG 그림(흐름, 구조, 비교, 순서). 내용 슬라이드 2장에 1개 이상.
7. `:::prof` 블록: **수업 녹음이 과목정보에 있을 때만.** 교수님이 한 말을 요지로, 언제 한 말인지. 녹음에 없는 말을 지어내지 않는다.
8. `:::exam` 블록(시험 포인트): 이 내용이 시험에 어떻게 나왔는지(기출이 있으면 "2026 제3회 필기 18번: ~ 을 고르는 4지 택일" 처럼 구체적으로), 또는 어떻게 나올 수 있는지(객관식 함정, O/X 로 뒤집기 좋은 문장, 단답으로 물을 용어, 나열형으로 물을 목록, 서술로 물을 비교). 외워 쓸 답안 문장 한두 개.
9. `:::warn` 블록: 헷갈리기 쉬운 점, 비슷한 용어 짝, 슬라이드 오류(고치지 말고 알림), 자료끼리 다른 점.
10. `:::repeat` 블록: 핵심을 다른 말로 3~4줄 불릿으로 되풀이. 과목 주문과 연결.

표지, 목차, 구분 슬라이드, 빈 슬라이드: 짧게(한글 200~600자). 목차는 항목마다 "무엇을 배우는지" 한 줄씩.

## 3. 분량

내용 슬라이드 한글 1200~2500자(SVG 제외), 단순한 슬라이드 400~900자.

## 4. 문법 (변환기가 이해하는 것만)

- 문단은 빈 줄로 구분. 굵게 `**...**`, 인라인 코드 `` `...` ``.
- 작은 제목 `#### 제목` (본문 안에서만. `##`, `###` 은 쪽 머리 전용).
- 불릿 `- ` (한 단계만), 번호 `1. `.
- 표: 파이프 표 (`| a | b |` 다음 줄 `|---|---|`).
- 수식이 꼭 필요하면 `$...$`, `$$...$$` (KaTeX). 한국어는 수식 밖에.
- 블록: 줄 처음 `:::이름`, 끝은 `:::` 만 있는 줄. 이름은 key, repeat, bg, step, fig, prof, exam, warn. **블록 안에 블록 중첩 금지.**
- 그림:
```
:::fig 그림 설명 한 줄
<svg viewBox="0 0 520 220" xmlns="http://www.w3.org/2000/svg">
  ...
</svg>
:::
```

## 5. SVG 규칙 (강의안용)

- 올바른 XML(`&` 는 `&amp;`, `<` 는 `&lt;`). `viewBox` 필수, 너비 300~560, width/height 속성 없음.
- 글자: `font-family="Pretendard, sans-serif"`, 크기 11~15, 한국어 가능.
- 색: 파랑 #4E79A7, 초록 #59A14F, 빨강 #E15759, 주황 #F28E2B, 보라 #7B61FF, 회색 #9AA0A6, 연한 배경 #EEF2FA, 글자 #222. 선 굵기 1.5~2.
- `id` 를 쓰면 반드시 `p<쪽번호>_` 로 시작(예 `p12_arrow`). 한 문서에 모든 쪽이 합쳐진다.
- 사각형 모서리는 둥글리지 않거나 아주 조금만: `rx` 는 0~3 (사용자 요청).
- 외부 이미지, 폰트, 스크립트, foreignObject 금지. 겹치는 글자 없게. 가능하면 PNG 로 렌더해서 직접 확인한다.

## 6. 좋은 예 (짧게 줄인 견본)

```
## p.14 주파수 대역별 특성
### 대본
:::key
무선은 주파수가 낮을수록 멀리, 벽 너머까지 가고, 높을수록 빠르지만 가까이만 가요.
:::

앞 슬라이드에서 허브가 집 안 기기들의 반장이라고 했죠. 반장이 친구들에게 말을 전하려면 "어떤 목소리로" 말할지 정해야 해요. 이번 슬라이드는 그 목소리의 높낮이, 곧 **주파수 대역(Frequency Band)** 을 봐요.

#### 슬라이드 글자 하나씩 읽기
표의 첫 줄은 "Sub-GHz (800~900MHz)" 예요. ...

:::bg
**주파수(Frequency)** 는 전파가 1초에 몇 번 출렁이는지예요. 단위 **Hz(헤르츠)** 는 "1초에 한 번"이에요. 2.4GHz 는 1초에 24억 번이에요. 자세한 건 기초 다지기 4단원에서 봐요.
:::

:::exam
2026 제3회 필기 20번은 NFC 의 특징을 고르는 4지 택일이었어요. 이 슬라이드에서는 "주파수가 낮을수록 투과력이 좋다" 를 O/X 로 뒤집어 묻기 좋아요(높을수록 좋다고 바꾸면 X).
:::

:::warn
2.4GHz 는 Wi-Fi, Zigbee, BLE 가 같이 쓰는 대역이라 서로 간섭할 수 있어요. "Zigbee 는 Wi-Fi 와 다른 대역" 이라고 쓰면 틀려요.
:::

:::repeat
- 낮은 주파수: 멀리, 벽 너머, 느림.
- 높은 주파수: 빠름, 가까이, 벽에 약함.
- 주문: 센서가 느끼고, 네트워크가 나르고, 허브가 판단하고, 기기가 움직여요.
:::
```
