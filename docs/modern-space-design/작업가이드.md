# 근대건축 디자인사 문제은행 HTML 작업 가이드 (상세판)

이 문서 하나와 `근대건축_디자인사_문제은행.html` 파일만 있으면, 다른 대화창의 다른 모델이 처음부터 이어서 작업할 수 있도록 썼다. "이런 것까지?" 싶은 내용도 다 적었다. 처음 보는 사람은 0절부터 순서대로 읽고, 급하면 12절 체크리스트로 바로 간다. 문서 안의 치환용 문자열은 전부 실제 파일에서 정확히 1회 존재하는 것을 확인했고, 10절의 편집 코드를 그대로 실행해 4부 더미를 넣고 11-4 테스트까지 통과하는 것도 확인했다(2026-09-13 기준 파일, 457문항).

목차
0. 이 프로젝트가 뭔지
1. 사용자와 대화할 때 지킬 것
2. 절대 규칙 (어기면 사용자가 바로 알아챔)
3. 파일 하나의 해부도
4. CSS 클래스 사전
5. 데이터 형식 사전 (PARTS, BANK, TIMELINE, FLOW, KEYYEARS, CATS, localStorage)
6. 스크립트가 하는 일 (채점 로직 포함)
7. 정리노트 작성법 (원문 + 쉬운 설명 + 그림)
8. 문제 작성법 (유형별 요령, 나쁜 예, 좋은 예)
9. 암기 팁, 연표 추가법
10. 실제 편집 절차 (복붙 가능한 코드)
11. 검증 절차 (복붙 가능한 코드)
12. 최종 체크리스트
13. 자주 생기는 문제와 해결
14. 이 파일이 만들어진 과정 (참고)
15. 부록: 4부 예시 한 세트

---

## 0. 이 프로젝트가 뭔지

- 과목: 근대건축 디자인사 (대학 강의). 사용자는 시험 대비용으로 쓴다.
- 중간고사 범위: 1부(미술공예운동), 2부(아르누보, 유겐트슈틸, 아르데코, 시카고 학파), 3부(빈 분리파, 바그너, 로스). 이미 파일에 들어 있다.
- 기말고사 범위: 아직 자료가 없다. 사용자가 나중에 강의자료(PDF, PPT, 캡처)를 올리면 4부부터 이어 붙인다.
- 시험 유형: 객관식, 주관식, T/F(O/X), 논술형. "어디서 어떻게 나올지 몰라서 전부 다 봐야 한다"가 교수 말. 그래서 모든 사실을 문제화한다.
- 교수가 알려준 기말 논술 예시(반드시 문제로 만들 것):
  - "하이테크 및 기계미학 건축물을 아는 대로 모두 쓰시오"
  - "프랭크 게리의 초기작과 최신작을 토대로 디자인 변화를 서술하시오 (사례도 제시해야 함)"
- 논술 출제 패턴: "~양식에 대해 아는 대로 모두 서술하시오". 그래서 논술 문제는 "핵심 항목 체크리스트" 방식으로 채점한다.

결과물은 HTML 파일 하나. 사용자는 이 파일을 브라우저로 열어서 공부한다. 서버 없음, 로그인 없음.

## 1. 사용자와 대화할 때 지킬 것

- 한국어. 기술 용어는 영어 그대로 써도 된다.
- 보고는 짧게, 바뀐 점 위주. 장황한 설명이나 자화자찬 금지.
- 문구 톤은 담백하게. 친근 유도 문구("말 걸어주세요" 같은 것) 금지.
- 사용자는 "문제가 너무 적다"는 말이 나오는 걸 싫어한다. 새 범위는 넉넉하게.
- 파일을 교체할 때는 한 줄 안내: "혹시 몰라 오답노트 탭에서 내보내기 한 번 해두고 파일 교체하세요."
- 사용자가 "만들어줘", "추가해줘", "고쳐줘"처럼 직접 요청하면 그 턴에 바로 만든다. 요청 없이 매 턴 파일을 다시 만들지는 않는다(토큰 절약).
- 결과 전달은 `present_files`로 HTML(필요하면 이 md도)을 보낸다. 파일 링크 없이 말로만 끝내면 사용자는 파일을 못 받는다.

## 2. 절대 규칙

### 2-1. 디자인
- Archisketch(archisketch.com) 스타일을 사용자가 직접 캡처로 지정했다. 요약하면 라벤더(#E9E7FF → 흰색) 그라데이션 히어로, 인디고 `#4E3FE5` 포인트, 흰색 알약 버튼과 인디고 알약 버튼(`border-radius:999px`), 흰 카드에 얕은 그림자, 큰 검정 헤드라인, Pretendard 계열 산세리프.
- 색은 이 팔레트 + 채점용 녹색(`#1F9D67`)과 붉은색(`#E14B4B`) + 연표 분류용 파스텔 8색 외에 추가하지 않는다. 새 분류 색이 필요하면 파스텔 톤 하나만.
- 기존 CSS 변수를 쓴다: `--primary`, `--primary-dark`, `--primary-soft`, `--primary-mid`, `--ink`, `--sub`, `--line`, `--soft`, `--ok`, `--ok-soft`, `--no`, `--no-soft`, `--r`(카드 radius 22px).

### 2-2. 문장부호
- **가운뎃점(·), em dash(—), en dash(–)를 화면 문구, 문제, 해설, 노트, 팁, 연표 어디에도 쓰지 않는다.** 사용자가 처음부터 요구한 조건이다. AI 냄새 난다고 싫어한다.
- 대체: 쉼표, 마침표, 슬래시(/), 화살표(→), 괄호.
- 유일한 예외: 스크립트 안 `function norm(...)` 한 줄(입력 정규화 정규식에 문자가 들어 있음). 검증 코드가 이 줄을 제외하고 센다.
- 물결(~)은 써도 된다. 예: "7~12개".

### 2-3. 내용
- 강의자료에 있는 사실만 쓴다. 외부 지식으로 살 붙이지 않는다. 사용자는 강의 기준으로 채점받는다. 강의자료가 통설과 다르면 강의자료를 따르고, 필요하면 노트에 "강의자료에는 X로 표기, 통상 Y"라고 병기한다(예: 카페 무제움 연도).
- 슬라이드 내용은 빠짐없이. 요약해서 빼먹지 않는다.
- 그림은 캡처를 base64로 파일 안에 넣는다. 외부 링크 금지(오프라인에서 열어야 함).
- 정리노트의 **원문 정리(`.orig`)는 절대 삭제, 축약, 문장 변경하지 않는다.** 논술 답안을 원문 문장으로 써야 하기 때문. 쉬운 설명은 그 위에 얹는다.

### 2-4. 기록 보존
- localStorage 키 `archhist_v2`를 바꾸지 않는다.
- 기존 문항의 `id`와 `q`를 바꾸지 않는다. 문항 삭제도 하지 않는다.
- 이유와 상세는 5-7절.

### 2-5. 동작
- 모든 버튼은 실제로 동작해야 한다. 장식용 버튼 금지.
- 외부 JS 라이브러리 금지. 폰트 CDN 하나(Pretendard)만 허용, 없어도 시스템 폰트로 동작.
- 파일을 `file://`로 열어도 동작해야 한다(fetch, module import 금지).

### 3-1. 검색용 마커 (파일에서 그대로 찾을 수 있는 문자열, 각 1회)

| 목적 | 찾을 문자열 |

| 새 문제 넣는 곳 | `/* ===== [문제 추가 지점]` |
| 범위 목록 | `var PARTS = ` |
| 문제 배열 | `var BANK = ` |
| 연표 사건 | `var TIMELINE = ` |
| 흐름도 막대 | `var FLOW = ` |
| 기준점 | `var KEYYEARS = ` |
| 연표 분류 | `var CATS = ` |
| 연표 원본 표 끝 | `</tbody></table>` |
| 팁 카드 마지막 | `<section id="tips"` 로 찾은 뒤 그 뒤 첫 `</div></section>` |
| 연표 분류 색 CSS 끝 | `.c-아르데코{--c:#F1E2A8}` |
| 흐름도 축 범위 | `var A=1850,B=1940,W=B-A;` |

### 3-2. 섹션 id 규칙
- `s0`은 전체 흐름. `s1`~`s7`이 1부, `s8`~`s14`가 2부, `s15`~`s19`가 3부.
- 새 섹션은 `s20`부터 번호를 이어 쓴다.
- `h2` 텍스트는 "N-M. 제목" 형식. 예: `4-1. 하이테크 건축의 배경`.
- `#toc` 버튼의 텍스트는 h2와 같게.

## 4. CSS 클래스 사전

### 4-1. 공통
| 클래스 | 뜻 |
|---|---|
| `.card` | 흰 카드. 제목은 안에 `<h3 style="margin-top:0">` 또는 `<b>` |
| `.wrap` | 본문 최대폭 820px 가운데 정렬 |
| `.btn` `.btn.primary` `.btn.danger` `.btn.sm` | 알약 버튼 |
| `.chip` `.chip.on` `.chip.on.soft` | 선택 칩. `on`은 인디고 채움, `on soft`는 연보라 채움 |
| `.pill.white` `.pill.solid` | 히어로용 큰 버튼 |
| `.row > .cap` | 설정 줄의 왼쪽 라벨 |
| `.muted` | 회색 보조 글씨 |
| `.tag.mcq/.short/.ox/.essay` | 유형 태그(파랑/주황/초록/보라) |
| `.expl.on.good/.bad/.neutral` | 채점 결과 박스 |
| `.toast` | 하단 알림. JS `toast("문구")` |
| `details.adv` | 접힌 고급 옵션 |

### 4-2. 정리노트
| 클래스/태그 | 뜻 |
|---|---|
| `h1.part` | 부 제목. `#note` 직속 자식이어야 함 |
| `section#sN > h2` | 단원 제목. 왼쪽 인디고 세로선 |
| `h3` | 소제목 |
| `.easy` | 쉬운 설명 박스(연보라 그라데이션). 안에 `.easy-h`(라벨 "쉽게 말하면") 필수 |
| `.orig` | 원문 정리 래퍼. 토글 대상 |
| `ul` `li` | 원문 불릿 |
| `ul.two` | 두 열 목록 |
| `ol.flow` | 번호 목록(s0에서 사용) |
| `.term` | 용어 설명 박스(연보라) |
| `.tip` | 팁 박스(연보라, term과 같은 스타일). `p.tip`도 됨 |
| `p.lead` | 회색 도입 문장 |
| `blockquote` | 인용, 명언 |
| `figure > img + figcaption` | 그림 한 장. 가로 최대 560px |
| `.grid > figure` | 그림 여러 장 격자(250px 이상 자동 열) |
| `.tocbtn[data-go]` | 목차 버튼. `.on`은 현재 단원 |
| `.notebar` | 보기 모드 바 |
| `.onlybar` | "그 단원만 보기" 모드에서만 보이는 이전/다음 바 |
| `#note.easyonly` | `.orig` 숨김 |
| `#note.origonly` | `.easy` 숨김 |
| `#note.only` | `.show`가 붙은 section과 h1.part만 표시 |

### 4-3. 암기 팁
| 클래스 | 뜻 | 마크업 |
|---|---|---|
| `.story` | 단계형 목록 | `<div class="story"><div><b>라벨</b><span>설명</span></div>…</div>` |
| `ul.mnem` | 라벨 있는 목록 | `<ul class="mnem"><li><b>1851</b> 설명</li></ul>` |

## 5. 데이터 형식 사전

### 5-1. PARTS
파일 안 실제 형태(공백 포함 그대로):
```js
var PARTS = [{"id": "1", "name": "1부 미술공예운동", "short": "1부", "scope": "중간"}, {"id": "2", "name": "2부 아르누보, 아르데코, 시카고", "short": "2부", "scope": "중간"}, {"id": "3", "name": "3부 빈 분리파와 근대건축", "short": "3부", "scope": "중간"}];
```
- `id` 문자열. BANK의 `part`와 일치.
- `name` 범위 칩에 표시. `short` 문제 헤더와 오답노트에 표시.
- `scope` 시험 구분. 값이 2종류 이상이면 "중간 범위 / 기말 범위" 칩이 자동 생성된다. 기말은 `"기말"`.
- BANK에만 있고 PARTS에 없는 part는 `"4부"`라는 이름으로 자동 등록되지만 보기 싫으니 꼭 추가한다.

### 5-2. BANK (문항)
공통 필드: `id`(선택), `type`, `part`, `unit`, `q`.

```json
{"id":"a1b2c3d4e5","type":"mcq","part":"1","unit":"1-2 철의 시대","q":"철골(강철)이 발명된 해는?","c":["1651년","1709년","1789년","1851년"],"a":1,"e":"1709년 발명되어 처음에는 순수 공업 재료로만 쓰였습니다."}
{"type":"short","part":"1","unit":"1-4 도시설계이론","q":"하워드가 제시한 전원도시의 최적인구는?","a":["32000","32,000","32000명","32,000명","3만2천","3만 2천명"],"e":"저서 내일(1898)에서 32,000명."}
{"type":"ox","part":"3","unit":"3-5 로스","q":"로스하우스 상부 주거는 녹색 대리석으로 마감되었다.","a":false,"e":"녹색 대리석은 하부 상업 공간, 상부는 매끄러운 회반죽."}
{"type":"essay","part":"2","unit":"2-6 아르데코","q":"아르데코 양식에 대해 아는 대로 모두 서술하시오.","points":["1925년 파리 국제 근대산업 장식예술 박람회의 이름에서 유래","1920년대 후반에서 30년대 파리의 현대적 양식을 대표"]}
```

필드 상세:
- `id`: 기존 457문항은 `md5(type + "|" + q)` 앞 10자리. **새 문항은 비워도 된다.** 로드 시 `ensureIds()`가 `type + "_" + hash(type|q)`로 채운다. 직접 넣고 싶으면 아무 고유 문자열이나 된다(영숫자 권장).
- `type`: `mcq` `short` `ox` `essay` 넷 중 하나. 소문자.
- `part`: 문자열. `"4"`. 숫자 4가 아님.
- `unit`: `"N-M 키워드"`. 문제 카드 헤더, 오답노트, 취약 단원 그래프에 그대로 보인다. 같은 단원은 철자까지 똑같이 쓴다(그래프가 문자열로 묶음).
- `q`: 질문. HTML 태그 넣지 말 것(`esc()`로 이스케이프되어 태그가 글자로 보임). 줄바꿈 넣지 말 것.
- 객관식 `c`: 보기 4개 배열. `a`: 정답 인덱스(0~3). 보기는 출제 때 섞인다.
- 주관식 `a`: 배열. `a[0]`이 대표 정답으로 화면에 표시, 나머지는 허용 표기로 "(허용: …)" 표시. `e`: 해설.
- O/X `a`: `true`/`false` (JSON boolean, 문자열 아님).
- 논술 `points`: 문자열 배열. 채점 체크리스트. `e` 없음.
- `e`: 해설. 한두 문장. 오답일 때 "정답은 X. 해설" 형태로 붙는다.

### 5-3. TIMELINE
```js
{"era":"철의 시대와 만국박람회 (1850-1900)","y":"1851","items":["런던 만국박람회 수정궁, 건물 전체를 유리로 시공"],"who":"조셉 팩스턴","cats":["철과 유리"]}
```
- `era`: 같은 값이 연속되면 하나의 시대 헤더. 시대 순으로 정렬해서 넣는다(스크립트는 정렬 안 함).
- `y`: 표시 문자열. `"1855, 1867"`, `"1820년경"`, `"1859-60"` 같은 형태 가능. 기준점 판정은 첫 4자리 숫자로 한다.
- `items`: 같은 해 사건들. 각각 한 줄로 표시.
- `who`: 인물. 없으면 `""`.
- `cats`: CATS에 있는 값 배열.

### 5-4. FLOW
```js
{n:"아르누보", s:1890, e:1910, p:[1890,1905], c:"아르누보"}
```
- `s`~`e` 연한 막대, `p` 진한 구간. 축은 `var A=1850,B=1940` 고정. 기말 범위가 1940 이후면 `B`를 넓히고, CSS 격자 `calc(100%/9)`의 9를 (B-A)/10으로, 눈금 루프 `y+=10`을 라벨 안 겹치게 `y+=20`으로 바꾼다.
- `c`: 분류명(공백 없이). `.c-분류` CSS가 있어야 색이 난다.

### 5-5. KEYYEARS, CATS
```js
var KEYYEARS = {"1851":"철과 유리 건축의 출발 신호", …, "1930":"라움플란의 완성"};
var CATS = ["배경","철과 유리","도시계획","미술공예","아르누보","시카고","빈","아르데코"];
```

### 5-6. 연표 원본 표 (접힌 것)
```html
<tr class="era"><td colspan="4">시대 이름 (연도 범위)</td></tr>
<tr><td class='y'>1977</td><td>사건. 사건2</td><td>인물</td><td class='k'>분류</td></tr>
```
(작은따옴표 class는 원본 그대로. 큰따옴표로 써도 됨.)

### 5-7. localStorage (진행 기록)
키 `archhist_v2`, 값은 JSON:
```js
{ "wrong": { "<문항id>": {"count":2, "lastAnswer":"내가 쓴 답", "missing":["빠진 항목"] 또는 null, "resolved":false, "ts":1726000000000} },
  "seen":  { "<문항id>": {"n":3, "ok":2} },
  "extra": [ {문항}, … ] }
```
- `wrong`: 오답노트. `resolved`가 true면 해결됨(다시 맞히면 자동 true).
- `seen`: 정답률 계산용.
- `extra`: 화면의 "문제 추가하기(JSON)"로 붙여넣은 문항. 파일과 무관하게 남는다.
- 왜 파일을 바꿔도 남는가: 브라우저가 `file://` 출처의 localStorage를 파일명과 상관없이 하나로 공유하기 때문(Chrome, Edge, Firefox). 다른 브라우저, 다른 PC, 시크릿 모드에서는 안 보인다. 그래서 "내보내기/가져오기"가 있다.
- 왜 id를 바꾸면 안 되는가: 오답노트는 id로 문항을 찾는다(`byId`). id가 바뀌면 그 오답은 목록에서 사라진다.
- 왜 `q`를 바꾸면 안 되는가: 기존 문항은 id가 명시돼 있어 `q`를 고쳐도 id는 유지된다. 그래도 바꾸지 말라는 이유는 오답노트에 저장된 `lastAnswer`와 표시되는 질문이 어긋나기 때문. 오타 수정처럼 의미가 안 바뀌면 `q`만 고쳐도 된다. id는 절대 건드리지 않는다.
- 같은 문제를 파일에도 넣고 사용자가 화면에서 `extra`로도 넣었다면 중복 출제된다. 파일에 반영한 뒤에는 "추가한 문제 모두 삭제" 버튼을 누르라고 안내한다.

| `buildScopeChips()` | 범위 칩 생성(PARTS + scope) |

채점 규칙(문항 쓸 때 알아야 함):
- 객관식, O/X: 클릭 즉시 채점. 정답 보기 녹색, 내 오답 붉은색, 해설 표시. 키보드 1~4, O/X, Enter(다음).
- 주관식: 입력을 `norm()`으로 정리 후 허용 답안 각각과 (1) 완전 일치 또는 (2) 한쪽이 다른 쪽을 포함(허용 답안 길이 2 이상, 내 답이 허용 답의 60% 이상 길이)하면 정답. 자동 채점이 틀렸을 때 "맞은 걸로/틀린 걸로" 버튼으로 뒤집을 수 있고, 뒤집으면 기록도 되돌린다.
  - 따라서 허용 답안에 띄어쓰기 변형은 넣을 필요 없음(공백 제거됨). 넣어야 하는 것: 한글/영문 표기, 줄임말, 숫자 표기(32000 / 3만2천), 별명.
  - "언윈"만 쓰면 "언윈과파커"의 60%가 안 되어 오답 처리됨. 두 명 다 써야 하는 문제라면 의도대로다.
- 논술: "모범답안 보기" → 항목 체크 → "채점하고 다음 문제". 체크 비율 70% 이상이면 통과, 미만이면 오답노트에 빠진 항목과 함께 저장. 세션 결과에 "논술 평균 포함률" 표시. "건너뛰기"는 기록 없음.
- 논술 문항 수가 많으면 세트 시간이 길어진다. "전체 섞기"에서는 유형 비율이 문항 수 비율대로 나오니 논술 문항은 전체의 10% 안팎(현재 40/457)을 유지한다.
- "아직 안 푼 문제" 모드는 `seen`에 없는 문항만. "오답만"은 `wrong`에서 미해결만.

## 7. 정리노트 작성법

### 7-1. 원문 정리(`.orig`)
- 슬라이드 순서를 따라 `h3` 소제목 + `ul/li`로 옮긴다. 슬라이드의 문장을 자르거나 합치지 않는다. 한 슬라이드가 문장 5개면 li 5개.
- 강의자료 표기 그대로(인명 표기, 연도, 숫자). 통설과 다르면 병기.
- 용어가 나오면 `<div class="term">용어 A는 …, B는 …</div>` 박스로 풀어준다(예: 주철/단철/강철).
- 인용문, 명언은 `<blockquote>`.
- 그림: 슬라이드 캡처를 `<figure>`로. 캡션 형식은 "건축가, 작품, 도시, 연도. 한 줄 설명" (예: `오토 바그너, 우편 저축은행, 빈, 1906. 메인 뱅킹 룸`). 사진이 2장 이상 연달아 나오면 `.grid`로 묶는다.
- 이미지 규격: JPEG, 가로 900px 이하, 품질 75~80. 한 장 30~80KB 목표. 파일 총합이 10MB를 넘기면 품질을 낮춘다.

### 7-2. 쉬운 설명(`.easy`)
```html
<div class="easy"><div class="easy-h">쉽게 말하면</div>
<p><b>한 줄 요약</b> 한 문장으로.</p>
<p>문단 2~5개. 중학생한테 말하듯. "~예요", "~했어요" 구어체, 가끔 반말 섞여도 됨.</p>
</div>
```
문체 원칙(사용자가 "유치하게 써도 되니 잘 외워지게"라고 함):
- 첫 줄은 무조건 `<b>한 줄 요약</b>`.
- 인물은 캐릭터로. "러스킨 아저씨는 잔소리꾼", "로스는 장식은 죄악 아저씨".
- 순서가 중요한 건 화살표: "농사 잘돼서 남는 게 생김 → 양털 공장 생김 → …".
- 헷갈리는 짝은 "주의:"로 바로 짚기.
- 사실은 원문에 있는 것 전부 넣되(연도, 이름, 숫자 포함) 문장은 짧게.
- 핵심어는 `<b>`. 한 문단에 3개 이내.
- 가운뎃점, dash 금지는 여기도 적용.
- 견본은 파일 안 `s2`(철의 시대), `s19`(로스)의 `.easy`.

### 7-3. 전체 흐름(`s0`)
새 범위가 들어오면 `s0`의 `ol.flow` 마지막 `li` 뒤에 새 범위 흐름을 한두 줄 추가한다. `s0`에는 `.easy`/`.orig`가 없으니 그냥 `li`만 추가.

### 7-4. 목차
`#toc` 안 마지막 버튼 뒤에 추가:
```html
<button class="tocbtn" data-go="s20">4-1. 제목</button>
```

## 8. 문제 작성법

### 8-1. 분량 (단원 = h2 하나)
| 유형 | 단원당 | 부(part)당 최소 |
|---|---|---|
| 객관식 | 15~20 | 60 |
| 주관식 | 10~15 | 35 |
| O/X | 10~15 | 35 |
| 논술 | 3~5 | 10 |

현재 1부 60/39/39/14, 2부 76/43/47/15, 3부 47/32/34/11 안팎. 이보다 적으면 "문제가 적다" 소리 나온다.

### 8-2. 뭘 문제로 만들 것인가
슬라이드의 모든 사실 단위를 뽑는다.
- 연도(발명, 완공, 결성, 발표), 생몰년
- 인물과 작품 짝, 작품과 도시, 작품과 층수/높이/인구/벽두께 같은 숫자
- 용어 정의(라움플란, 시카고 창, 갤러리 형)
- 명언, 표어, 책 제목, 논문 제목
- "특징이 아닌 것", "옳지 않은 것" (헷갈리는 짝 활용)
- 원인과 결과(왜 철을 썼나, 왜 타일을 썼나)
- 비교(A와 B의 차이)
같은 사실을 유형 바꿔 2~3번 낸다. 예: 수정궁 설계자 → 객관식, 주관식(이름 쓰기), O/X("수정궁은 에펠이 설계했다" false).

### 8-3. 유형별 요령
객관식
- 오답 보기는 같은 범주에서(인물 문제면 다른 인물, 연도면 근처 연도). 엉뚱한 보기 금지.
- 정답 위치는 신경 안 써도 됨(섞임). "위의 모두", "정답 없음" 금지.
- 문장은 "~은?" "~로 옳은 것은?" "~이 아닌 것은?" 형태.

주관식
- 답이 한 단어나 숫자, 짧은 구인 것만. 설명형은 논술로.
- `a[0]`은 강의자료 표기. 뒤에 영문, 줄임말, 숫자 변형.
- 두 사람 이름을 묻는 문제는 허용 답에 "A와 B", "A, B", "A B" 세 가지를 넣는다.
- 연도는 `["1906","1906년"]`.

O/X
- 절반은 false. false 진술은 헷갈리는 요소 하나만 바꾼다(인물, 연도, 도시 바꿔치기, 반대 개념).
- "항상", "절대" 같은 극단 표현으로 낚지 않는다.
- 해설에 정답 근거를 반드시.

논술
- `q`는 시험 문장 형식 그대로: "~에 대해 아는 대로 모두 서술하시오", "~을 비교 서술하시오", "~의 변화를 사례를 들어 서술하시오".
- `points`는 원문 슬라이드 문장을 그대로(7~12개). 답안 뼈대 순서(배경 → 주장 → 형태 → 인물과 작품 → 한계와 영향)로 정렬.
- 교수 예시 문항은 반드시 넣는다. 비교형(초기작 vs 최신작)은 항목 앞에 "초기:", "최신:" 라벨.

### 8-4. 나쁜 예와 좋은 예
나쁜 객관식: `"q":"다음 중 옳은 것은?"` (주제 없음)
좋은 객관식: `"q":"빈 우편저축은행의 완공 연도는?","c":["1895년","1898년","1901년","1906년"],"a":3`

나쁜 주관식: `"q":"아르누보의 특징을 쓰시오"` (여러 문장, 자동 채점 불가) → 논술로
좋은 주관식: `"q":"아르누보의 독일 명칭은?","a":["유겐트슈틸","Jugendstil"]`

나쁜 O/X: `"q":"아르누보는 좋은 양식이다."` (사실이 아님)
좋은 O/X: `"q":"타셀 저택은 1911년 작품이다.","a":false,"e":"타셀 저택은 1893년, 오르타 저택이 1911년입니다."`

### 8-5. 문자열 안전
- JSON은 Python `json.dumps(..., ensure_ascii=False)`로만 만든다. 손으로 이스케이프 하지 않는다.
- 질문 안에 큰따옴표가 필요하면 작은따옴표나 괄호로.
- `<`, `>`, `&`는 `esc()`가 처리하지만 굳이 쓰지 않는다.

## 13. 자주 생기는 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 파일 열면 문제풀기 카드가 비어 있고 콘솔 에러 | BANK JSON 문법 오류 | 11-1 실행. `json.dumps`로만 생성 |
| "출제 가능 0문항" | part가 문자열이 아니거나 type 오타 | `"part":"4"`, type 소문자 |
| 범위 칩에 "4부"만 뜨고 이름 없음 | PARTS 미추가 | 10-6 |
| 새 분류 막대가 회색 | `.c-분류` CSS 없음 | 9-2의 4번 |
| 연표 표의 시대 행 왼쪽에 네모 | 세로 연표 CSS가 `.tl`로 되어 있음 | 반드시 `#tl`로 |
| 목차 "그 단원만 보기"에서 부 제목이 안 보임 | `h1.part`가 `#note` 직속이 아님 | section 밖, `#note` 바로 아래 |
| "쉬운 설명만"에서 원문이 안 사라짐 | `.orig` 래퍼 없음 | 원문을 `<div class="orig">…</div>`로 감쌈 |
| 주관식이 맞는 답인데 오답 처리 | 허용 표기 부족 | `a` 배열에 표기 추가. 사용자는 "맞은 걸로" 버튼으로 임시 대응 가능 |
| 오답노트가 사라짐 | id 변경, 저장 키 변경, 다른 브라우저 | 5-7절. 백업 JSON이 있으면 가져오기 |

| 마커 `assert count==1` 실패 | 이전 작업에서 이미 추가됨 | 10-2 출력을 보고 현재 상태에 맞게 위치 재지정 |

## 14. 이 파일이 만들어진 과정 (참고)

소스 전부는 `근대건축_문제은행_소스.zip`에 있다(source/, tests/, docs/). 사용자가 이 zip을 같이 올리면 빌드 방식(zip 안 README.md)으로 작업해도 되고, 없으면 이 문서 10절대로 HTML을 직접 편집한다. 두 방식의 결과는 같다. 코드 스타일은 `CODING_GUIDELINES.md`, 검증 결과는 `VERIFICATION_REPORT.md`를 본다.
1. 사용자의 이전 HTML(정리노트, 연표 표, 서술형 36, 객관식 42, 흑백 디자인)을 입력으로 받음.
2. Python으로 `<section id="note">`와 연표 표, ESSAY 배열을 추출.
3. 노트 텍스트를 다 읽고 부별로 `bank1.py`, `bank2.py`, `bank3.py`에 객관식/주관식/O/X를 튜플로 작성(각 문항에 unit 부여). 원본 ESSAY 36개 + 비교형 논술 4개 추가. id는 `md5(type|q)[:10]`.
4. `template.html`에 CSS, 마크업, 스크립트, `/*__BANK__*/` 같은 플레이스홀더를 두고 `build.py`가 치환.
5. 연표 표를 파싱해 TIMELINE JSON 생성, 분류 8개로 정규화. FLOW는 강의에서 언급된 연도로 직접 작성.
6. `easy.py`에 섹션별 `.easy` HTML과 팁 페이지 HTML. 빌드 시 `<h2>` 뒤에 삽입, 원문은 `.orig`로 감쌈.
7. jsdom으로 457문항 자동 풀이, `node --check`, 문장부호 검사.
8. 사용자 피드백으로 고친 것: 가운뎃점 제거, 연표 시각화(흐름도+세로 연표), 표의 네모 버그(`.tl` → `#tl`), 목차 "그 단원만 보기", 쉬운 설명과 암기 팁.
